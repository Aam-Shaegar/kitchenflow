# KitchenFlow — требования к проекту

KitchenFlow — backend платформы доставки еды, связывающий пользователей и рестораны.
Проект включает основной API, PostgreSQL и отдельный сервис ресторана для демонстрации интеграции.

## Пользовательские сценарии

- Просмотр ресторанов, фильтрация открытых заведений, просмотр меню и доступных блюд.
- Одна активная корзина пользователя; блюда из разных ресторанов нельзя смешивать.
- Изменение количества, удаление позиций и очистка корзины.
- Создание заказа с адресом доставки и ключом идемпотентности.
- Сохранение названия и цены блюда на момент заказа; денежные суммы в копейках.
- Просмотр заказов, текущего статуса и истории изменений.
- Отмена заказа до начала приготовления и повтор интеграции после сбоя.

## API партнёров и интеграция

- Регистрация ресторана, изменение описания и признака доступности.
- Управление категориями, блюдами, ценами и доступностью меню.
- Просмотр входящих заказов ресторана.
- Отправка заказа сервису ресторана по HTTP и получение статусов через callbacks.
- Идемпотентная обработка создания заказов и событий изменения статуса.
- Проверка допустимых переходов между статусами заказа.
- Демонстрационный ресторан с автоматическим и ручным режимами, отказами и сбоями.

## Технические требования

- Go, PostgreSQL, версионируемые SQL-миграции и запуск через Docker Compose.
- Два запускаемых сервиса: `kitchen-api` и `restaurant-mock`.
- OpenAPI-спецификация, описание доменной модели и архитектуры.
- Диаграммы пользовательского пути и пути ресторана, C4 и схема базы данных.
- Модульные тесты, статический анализ и сценарий сквозной проверки.
- Документированные ограничения MVP: нет клиентского интерфейса и полноценной аутентификации.
